# 《中继站》开发计划 · 第一阶段「基础验证」

> v0.1｜2026-09-06｜对应《中继站策划案 v0.1》6.2 阶段表第一行「基础验证」
> 推进顺序：W1 架构地基 + 格子地图 → W2 角色 + 设施 + 任务 → W3 行为闭环 + UI + 集成
> 任务不指定负责人，由团队按依赖关系认领；每周演示可运行版本（对应策划案 6.3）。

## 1. 目标与范围

**阶段目标**：灰盒格子地图中，一名角色可完成一次修复任务闭环。

**本阶段三个重心**（2026-09-06 确认）：

1. **技术架构与模块接口**：搭建支撑 4 名程序员并行开发的分层架构，冻结接口契约 v1；
2. **格子地图架构**：用格子（Tile）表达圆环形基地，含数据模型、渲染与寻路；
3. **三人角色架构**：角色数据与行为框架按三人设计（需求、专长、任务选择），本阶段先以 1 人跑通闭环。

**阶段交付物**：可运行的灰盒 Demo 场景（验收标准见 §10）+ 冻结的模块接口契约（§8）。

## 2. 技术架构约定

### 2.1 分层原则：模拟层与表现层分离

| 层 | 目录 | 职责 | 约束 |
| --- | --- | --- | --- |
| 模拟层 | `core/` | 游戏规则：时间、地图数据、角色、任务、设施 | **禁止引用 Node / 场景 / PackedScene**；仅允许 Godot 基础值类型（如 `Vector2I`） |
| 表现层 | `game/` | Node 场景、渲染、输入、UI、音画反馈 | 只通过接口与事件读写模拟层，不私藏游戏状态 |

理由：模拟层不依赖 Node 才能做单元测试；三人行为逻辑、任务分配等核心规则可脱离引擎调试；为阶段二资源/氧气模拟和后续存档留出干净内核。

### 2.2 目录结构

```
res://
├── core/                      # 模拟层（禁 Node）
│   ├── Common/                # 值对象、通用工具
│   ├── Events/                # IGameEvent 定义 + IEventBus
│   ├── Time/                  # 游戏时钟（倍率/暂停/累计分钟）
│   ├── Map/                   # 格子数据模型、功能区、寻路封装
│   ├── Characters/            # 角色数据、需求框架、行为状态
│   ├── Tasks/                 # 任务生命周期、任务板
│   └── Facilities/            # 设施状态机
├── game/                      # 表现层
│   ├── Autoloads/             # GameRoot.cs（组合根，唯一 Autoload）
│   ├── Main/                  # Main.tscn 主场景
│   ├── Map/                   # MapView（TileMapLayer 渲染、hover 高亮）
│   ├── Characters/            # CharacterAgent（Node2D，移动与头顶标签）
│   ├── Facilities/            # FacilityView（状态着色/图标）
│   ├── Input/                 # 点击拾取、选中逻辑
│   └── UI/                    # 时间条、设施面板等 Control
├── resources/                 # .tres 数据定义（角色×3、设施、地图布局）
├── tests/                     # core 层单元测试（xUnit）
└── docs/
```

命名空间：`RelayStation.Core.*` / `RelayStation.Game.*`（程序集名保持 `Online_AI_Town` 不改，命名空间仅内部使用，2026-09-06 确认）。

### 2.3 全局服务与 Autoload

- **只注册一个 Autoload：`GameRoot`**（`game/Autoloads/GameRoot.cs`），作为组合根构建并持有模拟层各服务；
- `GameRoot._Process` 按时间倍率驱动 `Simulation.Tick()`；
- 表现层节点通过 `GameRoot.Instance.Simulation` 获取服务，或订阅事件总线；
- 明确禁止：在其他 Node 里用静态可变状态当全局变量。

### 2.4 数据驱动

用 Godot `Resource`（.tres）承载可配置数据，策划后续调数值不改代码：

- `CharacterDef`：id、姓名、出身、专长（影响效率的作业类型）、特质占位——**建满 3 份**；
- `FacilityDef`：id、名称、占地格、修复耗时（游戏分钟）、初始状态；
- 地图布局：格子数据 + 功能区划分（W1 内定稿为 .tres 或代码常量，原型从简）。

### 2.5 协作与工程约定

- 引擎版本锁定：Godot 4.7.2 stable (mono)，.NET SDK 8；
- 分支：`main` 受保护；`feature/<模块>-<任务号>` 分支开发，PR 至少一人 review（任务跨模块时由主程 review）；
- PR 检查清单包含：`core/` 无 Node 引用、接口变更同步更新本计划 §8；
- 代码风格：`.editorconfig` 已有，缩进与命名以现有配置为准；
- 每周集成演示可运行版本（先保证 `main` 可运行，再演示功能）。

## 3. 地图架构（格子地图）

### 3.1 圆环基地的格子化方案（W1 初定稿）

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| **A：环形格子近似（倾向）** | 方形网格上按「到中心距离 ∈ [内径, 外径]」生成环状走廊，5 个功能区沿环分布为局部加宽舱室 | 俯视直观符合策划案「圆环形基地」；TileMap/AStarGrid2D 原生支持 | 圆环用方格拼出有锯齿感，需灰盒验证观感 |
| **B：环展开条带** | 圆环切成段铺成横向长条走廊（类 FTL 舱段） | 实现最简单、格子利用率高 | 与「圆环」表现不符 |

**决策规则**：W1 先做 A/B 灰盒对比，以观感 + 实现成本定稿；默认 A，观感不佳降级 B。参考尺寸：方案 A 约 48×48 格、环外径约 20 格、走廊宽 3 格、Tile 32×32。

### 3.2 格子数据模型

- `CellKind`：`Vacuum`（不可通行）/ `Floor` / `Wall` / `Door` / `FacilitySlot`；
- `ZoneId`：`Living` / `Power` / `LifeSupport` / `AirlockStorage` / `Communication` 五个功能区，灰盒用底色区分；
- `IGridMap` 提供：格子查询、可通行判定、功能区归属查询；
- 坐标换算统一走 `MapView.LocalToMap / MapToLocal`，模拟层只认 `Vector2I` 格子坐标。

### 3.3 寻路

- 封装 Godot `AStarGrid2D`（非 Node 类型，允许在 `core/` 使用）实现 `IPathfinding`；
- 开发期提供路径调试可视化（`game/` 内画线），验收后可隐藏。

### 3.4 渲染

- 使用 `TileMapLayer`（Godot 4.3+，勿用已废弃的 `TileMap` 节点）；
- 灰盒阶段：地板/墙体用纯色 Tile，功能区以底色区分，设施占位用色块 + 文字。

## 4. 角色架构（面向三人的设计）

### 4.1 三层数据模型

| 层 | 类型 | 说明 |
| --- | --- | --- |
| 定义 | `CharacterDef`（Resource，建满 3 份） | 维修人员 / 系统操作员 / 外勤作业员：出身、专长、特质占位 |
| 模拟 | `CharacterSim`（core） | 当前状态、所在格、当前任务、需求快照、效率倍率 |
| 表现 | `CharacterAgent`（Node2D） | 沿路径移动、头顶任务标签；只读 `CharacterSim` 并订阅变更事件 |

**角色数量由配置驱动**：演示场景默认 1 人，改资源数组即可 3 人同屏——这是「三人架构」在本阶段的落地方式。

### 4.2 需求框架（占位）

- `INeedSystem` 按策划案定义呼吸 / 进食 / 休息三项需求（0~100），本阶段仅按时间缓慢衰减、**不致命、不生效死逻辑**；
- 目的：冻结需求数据结构与更新接口，阶段二接入真实生存压力时不动架构。

### 4.3 行为状态机

`Idle → Moving → Working → (Done | Interrupted) → Idle`

- 阶段一行为简化为「玩家下达修复任务 → 角色认领 → 寻路前往 → 执行 → 完成」；
- 任务选择接口 `TaskBoard.PickFor` 的签名按「需求 + 优先级 + 可用性」预留，阶段一实现为「玩家显式指派」，阶段二接入工作优先级面板；
- 专长通过 `WorkSpeedMultiplier` 影响修复耗时（接口本阶段接通，数值从简）。

## 5. 任务与设施系统（最小闭环）

### 5.1 任务生命周期

`Pending → Assigned → InProgress → Done / Cancelled`

- 本阶段唯一任务类型：`RepairTask`（目标设施 + 修复耗时）；
- 玩家点击损坏设施 → 面板点「修复」→ 任务进入 `Pending` → 空闲角色认领。

### 5.2 设施状态机

`Damaged → UnderRepair → Operational`，状态变化发事件，`FacilityView` 变色呈现。
本阶段放 1~2 台损坏设施（建议其中一台为制氧机，为阶段二留语义），不接真实运行效果。

### 5.3 Demo 剧本（修复闭环）

1. 运行 `Main.tscn`，显示灰盒环形基地与待机角色；
2. 点击损坏设施 → 弹出面板显示名称 / 状态 / 修复按钮；
3. 点击「修复」→ 角色头顶出现任务标签，自动寻路前往；
4. 到达后进入 Working，进度按游戏分钟推进（受专长效率影响）；
5. 完成 → 设施变色为 Operational，角色回到 Idle，事件日志（DebugOverlay 打印即可）。

## 6. 时间系统

- `IGameClock`：累计游戏分钟、暂停、1×/2×/4× 倍率；
- 换算：正常速度下 **1 现实秒 = 1 游戏分钟**（倍率即 ×60 ×N）；
- `GameMinuteElapsed` 事件供需求衰减等系统订阅；
- 顶部时间条提供暂停/加速按钮与游戏时钟显示。

## 7. 最小 UI

| 组件 | 内容 |
| --- | --- |
| 时间条 | 游戏时钟、暂停/1×/2×/4× 按钮 |
| 设施面板 | 点击设施显示：名称、状态、修复按钮 |
| 头顶标签 | 角色当前任务文字（阶段一用 Label，不做气泡美术） |
| DebugOverlay | 鼠标格子坐标、路径可视化、事件日志打印（仅开发期） |

## 8. 模块接口契约（C# 草案，W3 评审后冻结 v1）

> 以下为签名级草案，实现细节由开发者填充；任何接口变更需同步修改本节并走 PR。

```csharp
namespace RelayStation.Core.Events;

public interface IGameEvent { }

public interface IEventBus
{
    void Publish<TEvent>(TEvent e) where TEvent : IGameEvent;
    void Subscribe<TEvent>(Action<TEvent> handler) where TEvent : IGameEvent;
    void Unsubscribe<TEvent>(Action<TEvent> handler) where TEvent : IGameEvent;
}
```

```csharp
namespace RelayStation.Core.Time;

public interface IGameClock
{
    double TotalGameMinutes { get; }
    bool IsPaused { get; }
    int SpeedMultiplier { get; }             // 1 / 2 / 4
    void SetPaused(bool paused);
    void SetSpeed(int multiplier);
    void Advance(double realSeconds);         // 由 GameRoot 驱动
    event Action<double>? GameMinuteElapsed;  // 每满 1 游戏分钟触发
}
```

```csharp
namespace RelayStation.Core.Map;

public enum CellKind { Vacuum, Floor, Wall, Door, FacilitySlot }
public enum ZoneId { Living, Power, LifeSupport, AirlockStorage, Communication }

public interface IGridMap
{
    int Width { get; }
    int Height { get; }
    CellKind GetCell(Vector2I cell);
    bool IsWalkable(Vector2I cell);
    ZoneId? GetZone(Vector2I cell);
}

public interface IPathfinding
{
    /// 格子路径（含起终点）；不可达返回空列表
    IReadOnlyList<Vector2I> FindPath(Vector2I from, Vector2I to);
}
```

```csharp
namespace RelayStation.Core.Characters;

public enum CharacterState { Idle, Moving, Working, Interrupted }

public sealed record NeedSnapshot(float Oxygen, float Food, float Rest); // 0-100

public interface INeedSystem
{
    void Update(CharacterSim c, double deltaGameMinutes);
    NeedSnapshot Read(CharacterSim c);
}

public sealed class CharacterSim
{
    public CharacterDef Def { get; init; } = default!;
    public CharacterState State { get; }
    public Vector2I Cell { get; }
    public ITask? CurrentTask { get; }
    public float WorkSpeedMultiplier { get; }   // 专长/需求 → 效率
}
```

```csharp
namespace RelayStation.Core.Tasks;

public enum TaskState { Pending, Assigned, InProgress, Done, Cancelled }

public interface ITask
{
    TaskState State { get; }
    FacilitySim? Target { get; }
    double RemainingGameMinutes { get; }
    bool CanAssign(CharacterSim c);
}

public interface ITaskBoard
{
    IReadOnlyList<ITask> Pending { get; }
    void Submit(ITask task);
    void Cancel(ITask task);
    ITask? PickFor(CharacterSim c);  // 阶段一：玩家显式指派；阶段二：需求+优先级
}
```

```csharp
namespace RelayStation.Core.Facilities;

public enum FacilityState { Damaged, UnderRepair, Operational }

public sealed class FacilitySim
{
    public FacilityDef Def { get; init; } = default!;
    public FacilityState State { get; }
    public Vector2I OriginCell { get; init; }
    public event Action<FacilitySim, FacilityState>? StateChanged;
    // 阶段二挂点：OnOperationalTick(deltaGameMinutes) —— 供电/制氧等运行效果
}
```

```csharp
// game/Autoloads/GameRoot.cs —— 组合根
public partial class GameRoot : Node
{
    public static GameRoot Instance { get; private set; } = default!;
    public Simulation Simulation { get; private set; } = default!;

    public override void _Ready() { /* 装配 IGameClock / IGridMap / IPathfinding / ITaskBoard / INeedSystem */ }
    public override void _Process(double delta) { Simulation.Clock.Advance(delta); Simulation.Tick(); }
}
```

## 10. 阶段验收标准（DoD）

1. `Main.tscn` F5 直接运行，无报错；
2. 灰盒环形基地完整显示，5 个功能区以颜色区分，含至少 1 台「损坏」设施；
3. 点击设施 → 面板显示名称/状态 → 点「修复」→ 角色自动寻路前往 → 进度推进 → 设施变色为「运行」（§5.3 剧本）；
4. 时间条暂停/1×/2×/4× 切换正常，游戏时钟换算正确；
5. 角色头顶显示当前任务文字；
6. 角色数量由配置驱动：改资源数组即可 3 人同屏，并完成一次走查（可延后项：仅验证 1 人）；
7. `core/` 下无 Node 派生类型引用（PR 检查项）；
8. 时钟换算、任务板流转、寻路各有至少 1 个单元测试通过。

## 11. 范围外（本阶段明确不做）

- 氧气/电力/食物的真实模拟与消耗结算（仅接口与占位数值）；
- 资源库存系统、EVA、叙事者与事件、存档、声音；
- 正式美术（全灰盒）与最终 UI 布局；
- 需求致死与死亡逻辑、工作优先级面板（接口已预留）。
