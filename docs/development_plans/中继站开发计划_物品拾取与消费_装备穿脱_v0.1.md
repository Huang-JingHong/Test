## 0. 本轮已对齐的口径（用户确认）

| 项 | 结论 |
| --- | --- |
| **物品基础单位（设计哲学）** | **「个」是唯一的基础单位**：重量、容量、拾取/转移、消耗、穿戴一律以个结算（`单位重量 × 个数`、**逐个转移**、消耗 1 个）。`ItemStack`（堆）**只是「用一张图显示多个」的表现分组**，不承载任何领域语义——后续任何涉及物品数量的逻辑都不得出现「整堆」概念 |
| 自动取用闭环 | **背包优先 + 就地补给**：饥饿/口渴时，若背包已有对应消耗品 → 就地消耗（耗时、恢复需求）；背包没有 → 自动前往地上最近的对应物品堆，**逐件拾入背包**（单趟上限 3 个且受容量限制），并就地消耗 1 个；之后再饿/渴直接吃背包里的，不再反复跑 |
| 右键菜单 | **仅**「有选中人物 且 鼠标悬停命中物品」时弹出（拾取 / 走到此处 /〔可装备时〕穿戴 / 预留扩展项）；其他位置右键维持现状=直接移动；无选中人物时不弹菜单、不显示蓝框 |
| 手动拾取 | **任务化 + 逐件转移**（参考《僵尸毁灭工程》）：走到物品格 → **每件一个转移周期**（默认 0.5 游戏分钟/件，可调）逐个搬入背包 → 直到**装不下下一件**（容量耗尽）或**堆已空**为止；无固定总时长，剩余件数留原地。完全装不下时 → 世界提示告知；**同一堆只派一人**（= 只对主选角色下个人任务，多选时其余人不参与） |
| 装备四项 | ①穿戴/卸下**任务化**（就地耗时，默认 5 游戏分钟，可被中止/抢占）；②**地面装备可直接穿戴**（右键菜单「穿戴」= 走过去取下并穿上，不先占背包）；③**装备效果生效**（除已有负重容量外，新增工作手套 +10% 工作效率、磁力靴 +20% 移动速度；保暖/护甲/供氧留后续）；④卸下优先回背包，**背包放不下则就地落地**（不阻断卸下） |
| 自动取用优先级 | 需求 < 30 → **P8**（抢占 P5 例行工作；可被「人物中止」忽略）；需求 < 10 → **Urgent**（不可被忽略）。两档阈值与数值均可调 |
| 蓝框与命中框 | 蓝框**偏小**（紧贴图标，外扩 1px）且与物品像素偏移对齐；悬停命中框**略小于整格**（图标 24 + 外扩 2 = 28 世界像素，格为 32） |

## 1. 现状与影响面

- **任务框架**：`ITask` + `FacilityWorkTask`（修复/建造/拆除三子类）+ `TaskBoard`（同目标去重、按优先级择优、抢占、挂起/恢复）。**任务目标只有设施**——`ITask.Target` 为 `FacilitySim?`，`Simulation.TryPickTask` 遇 `Target == null` 直接失败；`TaskBoard.Submit` 以 `ReferenceEquals(t.Target, task.Target)` 去重。**任务不存档**（读档归一）。
- **物品**：`ItemDef`（Id/DisplayName/MaxStack/IconTexturePath/WeightKg/EquipSlot/ContainerCapacityKg）、`ItemStack`（格 + 像素偏移 + 数量）、`ItemRegistry`（拆堆/扣空回收/按格查询）、`GroundItemStore`（地上可达零件库存视图）；地上堆随存档保存（`ItemPlacement`，资源引用，新物品类型自动兼容）。**无拾取/搬运/消耗**；`ItemDef` 无「可食用/恢复量/效率加成」一类字段。
- **背包**：`CharacterInventory`（`TryAdd`/`Remove`/`TryEquip`/`Unequip`/`Restore`，容量=基础+容器；只管重量）；写入口 `Simulation.TryAddItemToInventory/TryEquipItem/UnequipItem`。**无「可装入上限」查询**（拾取需要「还能装几个」）。
- **需求**：`NeedSystem`（9 项，`Read`/`Set`/`Update`，`NeedsChanged` 经 Simulation 转发 EventBus）。**不驱动行为**、**无「恢复某项需求」接口**。
- **角色**：`CharacterSim`（Idle/Moving/Working/Interrupted、CurrentTask、Path、IsManualMove、忽略清单、Inventory）；效率倍率只在「专长匹配」时生效（`GetWorkMultiplierFor`）；移动速度是全局常量 `Simulation.WalkCellsPerGameMinute = 3`。
- **输入/表现**：`InputPicker`（左键点击按「角色 → 设施 → 物品」命中、框选、右键 `RightClicked(世界坐标)`）；物品命中是**整格**判定，只有**黄色**选中描边（`ItemStackView.Selected`）；**无悬停**、**无右键菜单**（右键当前直接 = 走到该处）。`WorldHint` 可复用为世界坐标短提示。
- **装配**：`Main` 构造设施类任务并 `TaskBoard.Submit`；`GameRoot` 加载 `PartsItem` 与开局散落（`ScatterItems`）、存档读写。
- 已确认：`ITask` 的生产实现只有 `FacilityWorkTask`（测试中无假实现），故接口新增成员不波及测试桩。

## 2. 任务框架扩展（core/Tasks）—— 三批共用地基

| 文件 | 改动 |
| --- | --- |
| `ITask.cs`（改） | 新增 4 个成员（见下表） |
| `TaskBoard.cs`（改） | `Submit` 去重键由「同 `Target`」改为「**同 Owner + 同 Target + 同 ItemTarget**」（Owner 为 null 时与旧规则等价，设施任务行为不变）；其余（择优/抢占/挂起/恢复）零改动——Owner 限制由任务自身的 `CanAssign/CanJoin/CanFit` 表达 |
| `FacilityWorkTask.cs`（改） | 实现 4 个新成员：`ItemTarget → null`、`Owner → null`、`PreferredWorkCell → null`、`IsStillValid → true`；现有行为零变化 |
| `Simulation.cs`（改） | `TryPickTask` 改为「**先校验有效性 → 再解析作业格**」：`IsStillValid()==false` → `FailPick`；作业格 = `PreferredWorkCell(c)` 优先，其次设施四邻（`FindWorkCell`）；**作业格 = 角色当前格时不寻路**，直接进入 Working + `StartWork()`；其余寻路逻辑不变 |

`ITask` 新增成员：

| 成员 | 语义 |
| --- | --- |
| `ItemStack? ItemTarget` | 物品目标堆（拾取/取用/穿脱类任务）；设施任务与「就地」任务返回 null |
| `CharacterSim? Owner` | 任务归属者：**个人任务**（仅本人可认领/加入，用于需求取用与玩家对某人下的指令）；**公共任务**为 null（设施作业） |
| `Vector2I? PreferredWorkCell(CharacterSim c)` | 首选作业格：非空则直接用该格（物品任务=物品所在格；就地任务=角色当前格）；null 表示沿用「设施占地格四邻中选最近可达格」 |
| `bool IsStillValid()` | 目标是否仍有效（物品任务=目标堆仍在场上且数量 >0；设施任务恒 true）；认领时与作业中每次推进前由模拟层/任务自身校验，失效即取消并重新找活 |

- 「个人任务只派本人」实现于任务自身的 `CanAssign/CanJoin/CanFit`（`Owner == null || ReferenceEquals(c, Owner)`），`TaskBoard` 无需特判；任务板按 Owner 去重可保证「同一人同一目标只有一个未结任务」。
- **个人任务的中止语义**（`Simulation.AbortCharacterWork`）：若手上任务为个人任务（`Owner == c`）→ **直接取消该任务**（个人指令无法转交他人，留在板上会成为无人能认领的僵尸任务）；公共任务（设施作业）维持现状（脱离本人、留在板上可被他人接手）。自动取用任务若被玩家中止，**下一分钟仍会按需求重新评估并可能再投**（与「小人饿了就该吃」一致；「长期禁止某人自主行为」不在本轮范围，见 §9）。
- **逐件转移与接口兼容**：转移类任务（拾取/取用/穿戴）没有固定总时长，`ProgressWork(double gameMinutes)` 内部改为「时间累加 → 每达到单件阈值转移 1 件 → 重置累加器 → 重复」，完成条件是**动态终点**（装不下 / 目标已空 / 计划件数用尽）——`ITask` 签名与任务框架扩展的 4 个新成员均无需变动。
- **任务不存档**（沿用现状）：读档时进行中的拾取/取用/穿脱任务一律消失，物品与背包按存档恢复。

### 3.2 拾取任务（core/Tasks/PickupTask.cs 新增）—— 逐件转移

- 语义：**逐件搬运**（无固定总时长）——走到目标堆所在格 → 反复「转移 1 个」：每个转移周期耗时 `TransferGameMinutesPerItem = 0.5` 游戏分钟（可调）；每个周期结束时执行**单件**操作：`ItemRegistry.Remove(堆, 1)` + `inventory.TryAdd(def, 1)`（单件失败即装不下，任务结束）。
- **完成条件（动态终点）**：①再装不下下一个（`MaxAddable(def) == 0`）②目标堆已空 ③计划件数用尽。计划件数 = 认领时估算的 `min(堆数量, 当时 MaxAddable)`（仅用于进度条与预估耗时；途中堆被他人取走或容量变化时实时重算并提前结束，**提前结束按正常完成处理**，已转移的留在背包）。
- 进度：`ProgressFraction = 已转移件数 / 计划件数`（计划为 0 时按 0）；`TotalGameMinutes` 仅作展示参考（计划件数 × 每件耗时），不参与判定。
- 失效：认领时/每次推进前 `IsStillValid()`（堆已被取空 → 结束 + 回调「物品已被取走」）。
- 取消/中止：**无回滚**——已转移的留在背包、未转移的留在地面。
- 回调：`Action<PickupOutcome>? onOutcome`（`Transferred`（含部分转移）/`Gone`（一件都没拿到就没了）/`NoCapacity`（一件都装不下）），供 Main 用 `WorldHint` 告知——沿用 `BuildTask(onAbandoned:)` 既有模式。
- 优先级：玩家指令默认 `TaskPriority.P5`；单件推进同样乘装备效率加成（见 §5）。

### 3.3 模拟层门面（core/Common/Simulation.cs）

| 方法 | 语义 |

## 9. 本轮明确不做（边界）

1. **放下/搬运/储物区**：地面物品的搬运任务、储物架与库存区、物品分类归置（本轮只有「拾取」单向流转）。
2. **背包体积/格子化**：仍只管重量（kg）。
3. **多人协作拾取**：同一堆只派一人执行；不做「一人装不下、第二人接着拿」的接力（剩余件数留在地面，玩家可再下指令）。
4. **需求惩罚与其余自主行为**：低需求导致的效率下降/扣血、以及如厕/洗澡/社交/娱乐/睡觉的自主满足行为（需设施、占用与排队系统）。
5. **装备的保暖/护甲/供氧等效果**：等温度/辐射/气体系统落地后再配；本轮只做工作效率与移动速度两项加成 + 已有负重容量。
6. **食物腐败、水污染、烹饪/净水等生产链**；消耗只做「吃/喝」原子行为。
7. **右键菜单的通用化**：本轮菜单只在「选中人物 + 悬停物品」时出现，空地右键仍是直接移动（不做「所有右键都弹菜单」）。
8. **任务存档**：进行中的拾取/取用/穿脱任务不存档（沿用现状）。
9. **整堆快捷操作**：不提供「一键拿完整堆」——转移一律**逐件**进行（与 §0 设计哲学一致，转移节奏可被玩家看到与中止）。
10. **自主行为开关**：不做「永久禁止某人吃饭/喝水」的玩家开关——被中止的取用任务会在下一次分钟评估时按需求重新考虑。
