# 《中继站》开发计划 —— 人物属性扩展（需求 / 生命值 / 装备背包 / 面板重排）v0.1

> 2026-09-26｜状态：**批次 A、B 均已实施并通过验证**（生命值 + 装备背包 + 存档 + 面板重排，见开发历史 no.43 / no.44）；同日小修：**排泄拆分为「排泄」与「排尿」两项**（需求共 9 项、增长来源解耦，见 no.45）
> 本文只描述「怎么做」；数值与实现范围已与用户逐项对齐（见第 0 节），未对齐项一律标注「后续」。

## 0. 本轮已对齐的口径（用户确认）

| 项 | 结论 |
| --- | --- |
| 需求系统 | **仅数值与 UI**：9 项需求（呼吸/进食/饮水/休息/排泄/排尿/卫生/社交/娱乐）的衰减与增涨 + 面板数值显示；不做惩罚、不做自主满足行为 |
| 生命值 | **仅数值与 UI**：HP 0~100（初始 100），本轮无伤害来源、无死亡结算 |
| 装备与背包 | **数据 + UI + 负重校验**：物品带重量、背包提供容量(kg)、装备槽可穿脱；不做物品拾取/搬运/消耗流转 |
| 装备效果 | 无属性效果（不加效率/护甲/供氧），只占槽位与重量 |
| 装备槽位 | 头部 / 身体 / 背部（背包）/ 手部 / 脚部（共 5 槽） |
| 负重口径 | 角色自身基础负重 15kg（写进 CharacterDef，可配）；背包作为「背部」装备提供额外容量（示例 20kg） |
| 物品重量 | 单位重量 × 数量 = 堆重；背包**只管容量(kg)**，不涉及体积/格子 |
| 排泄/排尿规则 | **2026-09-26 修订**：拆为「排泄」与「排尿」两项且来源解耦——排泄 = 饱食值×0.0002 每游戏分钟、排尿 = 饮水值×0.0003 每游戏分钟；各自来源为 0 时对应需求零增长、各自封顶 100；两者互不影响（防「只吃不喝却排尿」让水回收系统虚空造水）；不做与卫生的联动；系数为可调常量 |
| 存档 | 9 项需求 / HP / 背包内容 / 已装备 全部纳入存档（旧档缺字段取默认；需求数组缺项按最佳值补齐） |
| 面板布局 | 紧凑单列 + 分区标题 + 超出可滚动 |

## 1. 现状与影响面

- 需求：`NeedSnapshot`（3 项 record）+ `NeedSystem`（占位衰减，`Dictionary<CharacterSim, NeedSnapshot>`）+ `INeedSystem`；`Simulation.OnGameMinuteElapsed` 每分钟调用一次；仅 `CharacterPanel` 读 3 条进度条。
- 生命值：**无**任何字段。
- 物品：`ItemDef`（Id/DisplayName/MaxStack/IconTexturePath，**无重量**）、`ItemStack`（地面物品堆，绑格子，随存档保存于 `GridMapData.Items`）、`ItemRegistry`（自动拆堆/扣空回收）、`GroundItemStore`（= 地上可达零件堆之和的库存视图）；物品已可点击选中（`InputPicker`/材料汇总栏）；**无**角色背包、**无**装备、**无**拾取/搬运任务。
- 角色：`CharacterSim`（状态机/格子/任务/路径/效率倍率/忽略清单）；`CharacterDef`（13 个 [Export]，含 `ActionSpriteFolderPath`）。
- 存档：`CharacterSaveEntry` 仅 `Def + Cell`（角色读档回满、回 Idle）。
- 面板：`CharacterPanel` 代码构建 UI（姓名/状态/中止按钮/专长/年龄性别/3 需求条/Bio），`Main` 里定尺寸 220 宽；右侧另有资源监测栏与材料汇总栏（贴在时间条下方、右边缘对齐），人物面板需与之在纵向上错开。

## 2. 需求系统扩展（core/Characters）

| 文件 | 改动 |
| --- | --- |
| `NeedId.cs`（新增） | 枚举 8 项，**顺序冻结**（存档按此顺序）：`Oxygen, Food, Rest, Water, Excretion, Hygiene, Social, Entertainment` |
| `NeedDirection.cs` + `NeedCatalog.cs`（新增） | 方向枚举（`Decreasing` 越大越好 / `Increasing` 越小越好）与 `NeedCatalog.Direction(NeedId)`；仅排泄为 `Increasing`。方向由 core 权威定义，UI 与测试共用，避免表现层各自猜测 |
| `NeedSnapshot.cs`（改） | 由 3 项扩为 8 项 record（同 NeedId 顺序）；新增 `const float Max = 100f`、`static NeedSnapshot Full`、`float Get(NeedId)`、`NeedSnapshot Set(NeedId, float)` |
| `NeedSystem.cs`（改） | 常量：沿用 呼吸 0.02 / 进食 0.015 / 休息 0.01；新增 饮水 0.025、卫生 0.008、社交 0.006、娱乐 0.007；排泄系数 饮水 0.0003、饱食 0.0002。`Update`：衰减型 `max(0, v - rate×delta)`；排泄 `min(100, v + (旧饮水值×0.0003 + 旧饱食值×0.0002)×delta)`。新增 `Set(c, snapshot)`（存档恢复，**不**触发事件）与 `event Action<CharacterSim, NeedSnapshot>? NeedsChanged`（每次 Update 后触发） |
| `INeedSystem.cs`（改） | 同步 `Set` 与 `NeedsChanged` |

- `Simulation` 转发：`NeedsChanged` → `EventBus.Publish(new NeedsChangedEvent(c, snapshot))`（`core/Events/GameEvents.cs` 新增事件类型，与现有 `CharacterStateChangedEvent` 同模式）。
- 测试：`tests/NeedSystemTests.cs` —— 8 项衰减方向与速率；排泄在 饮水=0/饱食=0 时不增长、满值封顶、下限 0；`Set` 恢复；事件触发次数。

## 3. 生命值（core/Characters/CharacterSim）

- `const float MaxHealth = 100f`；`float Health { get; internal set; }`（初值 `MaxHealth`）；`void ApplyHealthDelta(float delta)`（clamp 0~Max，供测试与后续伤害/治疗接入）。
- 本轮唯一写入方是存档恢复（`internal set` 在同程序集内可用）。
- 显示：`100/100`，与需求条同风格（红色条）。

| 文件 | 改动 |

| `EquipmentSlot.cs`（新增） | 枚举 `None, Head, Body, Back, Hands, Feet`（`None` = 不可装备） |

## 5. 角色背包与装备（core/Characters）

| 文件 | 改动 |
| --- | --- |
| `InventoryEntry.cs`（新增） | `record InventoryEntry(IItemDef Def, int Count)`（普通记录，不参与 .tres） |
| `CharacterInventory.cs`（新增） | 见下 |
| `CharacterSim.cs`（改） | 新增 `CharacterInventory Inventory { get; }`，构造时以 `def?.BaseCarryCapacityKg ?? 15` 创建 |
| `CharacterDef.cs`（改） | 新增 `[Export] float BaseCarryCapacityKg = 15`（三个角色 .tres 可不配即取默认） |

`CharacterInventory` API（全部纯 C#、可引擎外测试）：

- 读：`Entries`、`Equipped`（`IReadOnlyDictionary<EquipmentSlot, IItemDef>`）、`BaseCapacityKg`、`CapacityKg`（= 基础 + Σ已装备容器容量）、`TotalWeightKg`、`IsOverloaded`、`CountOf(def)`。
- 写（带校验）：`bool CanAdd(def, count)`、`bool TryAdd(def, count)`、`int Remove(def, count)`、`bool TryEquip(def)`（物品须在背包内且 `EquipSlot != None`；同槽已占用则旧装备回背包，回不去则拒绝）、`bool Unequip(EquipmentSlot slot)`（卸下前校验容量，超容量拒绝）。
- 存档恢复：`internal void Restore(equipped, entries)`（**不做容量校验**，超重也照原样恢复）。
- 不变量：装备中的物品不在 `Entries` 里；卸下/替换时回到 `Entries`；数量归零即移除条目。

模拟层写入口（`core/Common/Simulation`，表现层不直接改状态 —— 与 `OrderMoveGroup`/`AbortCharacterWork` 同约定）：

- `bool TryEquipItem(CharacterSim c, IItemDef def)`
- `bool UnequipItem(CharacterSim c, EquipmentSlot slot)`
- `bool TryAddItemToInventory(CharacterSim c, IItemDef def, int count)`（本轮供存档恢复与后续拾取接入；无 UI 入口）

- 测试：`tests/CharacterInventoryTests.cs` —— 基础负重只算背包内物品；装备背包后容量提升；超重 `TryAdd` 拒绝；同槽替换（旧装备回背包）；卸下超容量拒绝；装备中的物品不出现在 Entries；`Restore` 可恢复超重状态。

## 7. 人物面板重排（game/UI/CharacterPanel）

结构（紧凑单列 + 分区标题 + `ScrollContainer`）：

| 区 | 内容 |
| --- | --- |
| 头部 | 姓名（★队长）、选择集提示、状态、**中止 (F)** 按钮、专长、年龄/性别 |
| 生存 | 呼吸 / 进食 / 饮水 / 排泄 / 休息 |
| 身心 | 卫生 / 社交 / 娱乐 / 生命值 |
| 装备 | 5 槽位行：`头部｜宇航头盔｜[卸下]`；空槽显示 `—` 且无按钮 |
| 背包 | 负重行 `负重 12.5 / 35.0 kg`（超重红字）+ 物品行 `通用零件 ×20（10.0 kg）`，可装备物品带 `[装备]` 按钮 |
| 底部 | Bio（多行，自动换行） |

- 指标行统一构件：`名称 Label(约 52px) + 细条 ProgressBar(高 8px，无百分比) + 数值 Label(约 56px，右对齐，文本 "80/100")`｜排泄行的数值仍是 `当前/100`，条随值升高变危险色（方向取 `NeedCatalog.Direction`）。
- 颜色警示带（可后调）：衰减型 `<30 红 / 30~59 黄 / ≥60 绿`；排泄反向 `≥70 红 / 40~69 黄 / <40 绿`；HP 恒为红条。
- 刷新策略：订阅 `NeedsChangedEvent` → 只刷新生存/身心行数值（每分钟 1 次，避免每帧重建）；装备/背包在选中、状态变化、穿脱操作后 `Refresh()` 全量刷新。
- 尺寸：`Main` 中面板宽度调整为约 240px，高度自适应并受屏幕高度约束（`ScrollContainer` 兜底）；右侧资源监测栏/材料汇总栏贴在时间条下方，人物面板须与其在纵向上错开（限高 + 滚动，避免遮挡）。

## 9. 本轮明确不做（边界）

1. 需求惩罚（低需求导致的效率下降、扣血、昏迷）与需求驱动的自主行为（自动去吃喝、上厕所、洗澡、社交、娱乐；需新增「使用设施/物品」任务、设施占用与排队）。
2. HP 的伤害来源、治疗、死亡与失败结算。
3. 装备的属性效果（效率/护甲/供氧等）。
4. 物品流转：地面拾取/放下、搬运任务、消耗品使用（吃饭/喝水/吃药）、任务消耗优先取用背包物品。
5. 背包的体积/格子化，以及需求与设施/物资的联动（饮水需水、进食需食物）。
