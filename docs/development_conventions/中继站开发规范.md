## 1. 技术架构约定

### 1.1 分层原则：模拟层与表现层分离

| 层 | 目录 | 职责 | 约束 |
| --- | --- | --- | --- |
| 模拟层 | `core/` | 游戏规则：时间、地图数据、角色、任务、设施、资源库存 | **禁止引用 Node / 场景 / PackedScene**；仅允许 Godot 基础值类型与 Resource（.tres 数据层例外） |
| 表现层 | `game/` | Node 场景、渲染、输入、UI、音画反馈 | 只通过接口与事件读写模拟层，不私藏游戏状态 |

理由：模拟层不依赖 Node 才能做单元测试；核心规则可脱离引擎调试；为后续系统留出干净内核。

### 1.2 目录结构

```
res://
├── core/                      # 模拟层（禁 Node）
│   ├── Common/                # Simulation 模拟核心组装
│   ├── Events/                # IGameEvent 定义 + IEventBus
│   ├── Time/                  # 游戏时钟
│   ├── Map/                   # 格子数据模型、功能区、寻路
│   ├── Characters/            # 角色数据、需求框架、行为状态
│   ├── Tasks/                 # 任务生命周期、任务板
│   ├── Facilities/            # 设施状态机
│   └── Resources/             # IResourceStore 资源库存
├── game/                      # 表现层
│   ├── Autoloads/             # GameRoot.cs（组合根，唯一 Autoload）
│   ├── Main/                  # Main.tscn 主场景
│   ├── TitleScreen/           # 标题界面（动态视频背景 + 静态回退）
│   ├── Map/                   # MapView（渲染）/ MapEditor（编辑建造）
│   ├── Characters/            # CharacterAgent（Node2D）、角色头像库 CharacterPortraitLibrary
│   ├── Facilities/            # FacilityView（状态着色）
│   ├── Input/                 # InputPicker、CameraController
│   ├── Save/                  # SaveGameResource / SaveGameService / SaveSlotDialog
│   ├── Cutscenes/             # 剧情动画框架（Actions/Scripts/Triggers 子目录）
│   ├── Audio/                 # 音库 MusicTrackDef/MusicLibraryResource、音频资产
│   ├── Video/                 # 视频资产（.ogv；Godot 原生仅支持 Ogg Theora）
│   ├── Textures/              # 贴图资产（根=地图/设施；ui/=菜单图标；characters/=角色立绘与头像）
│   └── UI/                    # 时间条、设施/人物面板、暂停菜单、对话框、菜单栏框架等 Control
├── resources/                 # .tres 数据定义（角色、设施、地图、音库、总配置）
├── tests/                     # core 层单元测试（xUnit，不进 .sln）
└── docs/
```

### 1.3 命名空间与程序集

- 命名空间：`RelayStation.Core.*` / `RelayStation.Game.*`；程序集名保持 `Online_AI_Town` 不改。
- 依赖方向唯一：`game → core` 单向；`core` 内禁止出现 `using RelayStation.Game`。

### 1.4 全局服务与会话流

- **只注册一个 Autoload：`GameRoot`**（`game/Autoloads/GameRoot.cs`），作为组合根构建并持有模拟层各服务（时钟/地图/寻路/任务板/需求/事件总线/备用零件库存）。
- 会话流：`Title` 态不构建模拟；标题界面调用 `StartNewGame(devMode)` / `LoadGame(slot)` 构建完成后切入主场景，`_Process` 仅在 `InGame` 态驱动 `Simulation.Update`。
- 表现层节点通过 `GameRoot.Instance` 访问模拟服务，或订阅事件总线；`GameRoot.SaveMap()` 仅开发者模式可覆写默认地图。
- 明确禁止：在其他 Node 里用静态可变状态当全局变量。

### 1.5 数据驱动

用 Godot `Resource`（.tres）承载可配置数据，数值调整不改代码；.tres 键使用 C# PascalCase 原名（[Export] 不做 snake_case 转换）：

- `CharacterDef`：id、姓名、出身、背景介绍 Bio、专长、特质、队长标记 IsCaptain、性别 Gender、年龄 Age、基础负重 BaseCarryCapacityKg（默认 15kg）、立绘 SpriteTexturePath、动作立绘文件夹 ActionSpriteFolderPath、默认头像 PortraitTexturePath；
- `FacilityDef`：id、名称、占地格、修复耗时、修复/建造/拆除耗时、修复与建造零件成本、**分类 Category**（建造面板按类过滤的依据）、初始状态、所属功能区、贴图路径（IconTexturePath 正常 / BrokenTexturePath 破损；未配置时建造面板与地图均回退占位色块）；
- `DemoConfigResource`：本局角色定义数组 + **地图初始摆件设施数组 Facilities** + 初始零件（改数组即可增减登场角色/初始设施）；**可建造设施目录**独立为 `FacilityCatalogResource`（`resources/facility_catalog.tres`）——与「地图初始摆件」解耦，新增可建造设施只需往目录追加一项并在其 .tres 上标注 Category；
- 地图布局 `GridMapData`、音乐音库 `MusicLibraryResource`。
- 素材路径一律写在 Def（.tres）中，表现层只认路径：设施与角色贴图见上；菜单图标走「菜单 Id → `res://game/Textures/ui/menu_<id>.png`」约定（无需额外配置）；任何路径缺失或加载失败均由表现层回退占位/文字，不报错中断。

## 2. 系统约定

### 2.1 地图

- `CellKind`（Vacuum/Floor/Wall/Door）为格子地形唯一表达；**设施不占用格子类型**（历史 FacilitySlot 已移除）：设备直接放置于地板之上；
- 设施占地阻挡为**动态判定**：Simulation 维护占地格集合（增删设施/撤销时更新）并以 `IsCellOccupied` 暴露，`GridPathfinding` 构造注入阻塞委托（通行 = 地形可通行且未被占用）；作业格筛选同样避让占地格；
- 旧数据兼容：历史 .tres（默认地图与旧存档槽）中残留的 FacilitySlot 值（4）由 `GridMapData.ToGridMap` 在强转前单点清洗为 Floor；
- 地图与空间站尺寸解耦：`RingMapGenerator.MapSize`（当前 72×72）只决定可玩格范围；空间站本体为**固定基准尺寸**（走廊 16~19、外壳 20、舱室 23~24 格半径），不随地图边长变化——放大地图只增加外围真空区域，环外由生成器 else 分支自然填充为 Vacuum；
- 默认地图 base_map.tres 的尺寸与当前生成器不符时（改了 MapSize 之后），`GameRoot.LoadOrGenerateMap` 忽略旧数据并重新生成落盘；
- `IGridMap` 提供查询/可通行/功能区归属（含 SetCell/SetZone/ClearZone 写入接口）；
- 坐标换算统一走 `MapView.LocalToMap / MapToLocal`，模拟层只认 `Vector2I` 格子坐标；
- 寻路为纯 C# A*（`GridPathfinding`，勿用引擎 AStarGrid2D——其引擎外构造崩溃）。

### 2.2 角色

- 三层数据模型，**数量由配置驱动**：`CharacterDef`（.tres 静态数值）→ `CharacterSim`（core 运行时状态）→ `CharacterAgent`（game 表现）；
- 表现层只读 `CharacterSim` 并订阅 StateChanged 事件，不私藏游戏状态；
- 行为状态机：`Idle → Moving → Working → (Done | Interrupted) → Idle`，由 Simulation 每帧驱动；
- 需求框架 `INeedSystem`（九项：呼吸/进食/饮水/休息/排泄/排尿/卫生/社交/娱乐，数值 0~100；**仅排泄与排尿为增长型且来源彼此独立**——排泄 = 饱食值×0.0002 每游戏分钟、排尿 = 饮水值×0.0003 每游戏分钟，各自来源为 0 时对应需求零增长（防「只吃不喝却排尿」使水回收系统凭空产水），各自封顶 100）当前为**仅数值**实现：不致命、不影响工作效率、不驱动行为；每推进一次发 `NeedsChanged`（经 `Simulation` 转发为 `NeedsChangedEvent` 上事件总线）供 UI 刷新数值，读档经 `Set` 覆盖且不发事件；快照的「最佳状态」为衰减型 100 / 增长型（排泄、排尿）0；`NeedId` **只可追加不可插入**（新需求一律追加在末尾，旧档缺项由 `NeedSnapshot.FromArray` 按最佳值补齐）；
- 生命值 `CharacterSim.Health`（0~100，初始满值）为**仅数值 + UI**：`ApplyHealthDelta` 是后续伤害/治疗的接入点，本阶段无伤害来源与死亡结算；生命值与九项需求随存档保存（`CharacterSaveEntry.Health/Needs`，旧档缺字段按默认恢复）；
- 背包与装备（**数据 + UI + 负重校验**，本轮无拾取/搬运/消耗流转）——`CharacterInventory`（挂在 `CharacterSim.Inventory`）：容量 = `CharacterDef.BaseCarryCapacityKg`（默认 15kg）+ Σ已装备容器（背包）容量，物品按「单位重量 × 数量」计重（`ItemDef.WeightKg`），**只管容量不涉及体积与格子**；五槽 `EquipmentSlot`（Head/Body/Back/Hands/Feet，`None`=不可装备），`ItemDef.EquipSlot` 定槽、`ItemDef.ContainerCapacityKg` 提供容量；装备中的物品不在背包条目里（换装/卸下回包），同种物品合并为一条记录；**写入口一律走 `Simulation.TryAddItemToInventory / TryEquipItem / UnequipItem`**（表现层不直接改模拟状态）；卸下或换装后超重则整笔拒绝，仅存档恢复可带回超重状态（`CharacterSaveEntry.Equipment/Inventory`，旧档缺字段 → 空背包）；
- 性别 `Gender`（Male/Female）与年龄 `Age` 写入 CharacterDef，由人物面板展示（不参与模拟规则）；
- 立绘与头像分离：地图用 `SpriteTexturePath`（立绘，按 `SpriteTargetHeightPx` 自适配高度缩放，未配置则沿用 CharacterAgent.tscn 内置占位贴图）；对话框用 `PortraitTexturePath`（默认即平静表情）；
- **头像表情约定**：表情为表现层概念（枚举 `PortraitExpression`：Calm/Smile/Angry/Cry/Hurt/Panic，默认 Calm）——Calm 直接用默认头像文件，其余表情按「默认头像路径扩展名前追加 `_表情后缀`」解析（如 `char_field_portrait.png` + Smile → `char_field_portrait_smile.png`），统一由 `CharacterPortraitLibrary.Get(def, expression)` 解析并缓存；表情贴图缺失回退默认头像，未配置头像路径返回 null 由对话框回退占位图。剧情脚本经 `DialogueAction` 的可选表情参数指定本句表情。

### 2.3 任务与设施

- 任务生命周期：`Pending → Assigned → InProgress → Done / Cancelled`（另可经 `Suspended` 挂起/恢复，见下「中止体系」）；`TaskBoard` 同目标未结任务去重防重复派单；
- **设施作业任务三层**：抽象基类 `FacilityWorkTask` 承载公共机制（进度推进、实时整件扣零件、多人协作、优先级、进度查询），子类只覆写「专长 + 三个钩子（`OnWorkStarted`/`OnWorkCompleted`/`OnWorkCancelled`）」表达差异化设施状态迁移——现有 `RepairTask`（维修）/ `BuildTask`（建造）/ `DemolishTask`（拆除）；**新增作业类型 = 新增一个薄子类，零改基类与任务板**；
- **多人与即时派工**：`FacilityDef.MaxWorkers` 为投入上限（默认 1 单人）；任务**发布当帧**由 `Simulation.AssignIdleWorkers()`（订阅任务提交事件自动触发）扫描全部空闲角色派工，人力立刻投入而不必等首人抵达；空闲角色可加入 **Assigned（首人途中）或 InProgress** 的任务（`ITask.CanJoin` / `TryJoin`），每人按各自专长倍率推进（总速度≈原始×人数）；
- **完工/打断即刻接活**：角色完成任务或被取消打断的当帧即重新找活（`Simulation.AdvanceWork` / `Interrupted` 分支调用 `TryPickTask`），持续接续直到确实无活可做；
- **任务优先级**（对齐《缺氧》/《环世界》）：`TaskPriority` 为**数字档 P1~P9（数值越大越优先，默认 P5）+ Urgent（紧急，单列最高档）**，由 `ITask.Priority` 承载、设施面板下拉可选；`TaskBoard.PickFor` 在「Pending 新任务 + 可加入任务」全部来源中按「优先级数值高者优先，同优先级按提交先后」统一择优（不再分两段扫描）；**Urgent 不受「人物中止」的忽略清单影响**（小人只要没死就得干；将来接入需求惩罚时同样 bypass）；
- **优先级抢占**（对齐《缺氧》的即时切换）：任务提交/恢复后 `Simulation.PreemptForHigherPriority()` 扫描全部手上有活的角色，用**纯查询** `ITaskBoard.PeekFor`（按 `ITask.CanFit`，忽略「角色须空闲」前置条件）求「若腾出手来」的最优可接手任务，**仅当优先级严格高于当前任务时**才打断（脱离当前工作、不加入忽略清单，随后当帧改做高优先任务）；同优先级不打断（保持「先到先得」、无抖动），数值有限且只升不降故不会来回抢占；正在执行右键移动指令（无 `CurrentTask`）者不打断——玩家指令优先；
- **中止体系**（2026-09-26，2026-09-27 调整被动中止口径）：①设施中止 = `ITask.Suspend()`（`TaskState.Suspended`，挂起而非取消）——保留进度与目标设施状态（含施工警戒线，不触发 `OnWorkCancelled` 回滚）、释放全部工作者、退出待处理队列但留在 `Active`，`ITaskBoard.Resume(task)` 恢复（回 Pending 并补发提交事件，当帧重新派工）；设施面板「中止」按钮触发、非维修态另有「继续」按钮，**维修态的恢复入口复用「修复」按钮**；②**被动中止**——只在「**全基地没有任何可达的零件来源**」时触发（模拟层想替认领者派备料却无处可取，见 `Simulation.TrySendForParts` 调 `SuspendForPartsShortage()`）：与主动中止**同一套语义**，仅额外置 `ITask.SuspendedByPartsShortage`（供面板显示「已中止（零件不足）」），Resume 时清除。**「某个工人自己的料用尽」不再挂起任务**——那只是他这一轮到头（见「份额制」bullet）；③人物中止 = `Simulation.AbortCharacterWork(c, ignoreCurrent)`——退出当前任务并把该任务（或备料任务所服务的作业）列入**本人**忽略清单（`CharacterSim.IsIgnoring`，`PickFor`/`PeekFor` 据此跳过），随即转向下一项；`Simulation.ClearIgnoredTasksFor(facility)` 在玩家对该设施重新下达指令时清除忽略（映射「任务再次被发布」）；入口为快捷键 F 与人物面板「中止 (F)」按钮；
- **手动移动**（2026-09-26，2026-09-27 改为「中止」语义）：右键点地 → `InputPicker.RightClicked(世界坐标)` → `Simulation.OrderMoveGroup(选中集, 目标格)`（目标格 + 四邻依次分配落脚格防叠放）→ `OrderMove` 先**视同主动中止**地退出当前工作（`AbortPersonalWork`——公共任务列入本人忽略清单、个人任务直接取消、备料任务连同它服务的那条作业一起忽略），再寻路进入手动移动（`CharacterSim.IsManualMove`），抵达后回 Idle 重新找活。即「右键移动 = 中止该工作 + 走过去」：**本人不会再自动折返原工作**，另一名赋闲的人会接手（轮末扫描自动开下一轮）。`Simulation.CanMoveTo(cell)` 供表现层做即时通行校验与提示。
- 取消释放全部工作者、任务失效由 Simulation 终态兜底回 Idle；后加入者寻路失败仅脱离本人（`ReleaseWorker`）；
- **设施状态机**：`Damaged ⇄ UnderRepair → Operational`、`UnderConstruction → Operational`、`Operational → Demolishing →（移除）`；状态变化发事件；`StartWork` 幂等（多人抵达不重复置设施状态）；设施作业态在**读档时归一**（建造中→不恢复、拆除中→运行、维修中→损坏，任务本身不存档，见 §2.7）；
- **建造/拆除 = 计时任务（与维修同构）**：正常模式下放置设施即以 `UnderConstruction` 占位入场（立刻占格阻挡、可被选中，并建视图），由 `BuildTask` 的工人按时间推进、**零件随进度从推进者自己的背包实时整件扣除**（认领时自动分配份额、并行取料；料尽即本人退场并自动开下一轮，无从取料才挂起＝被动中止，补料后经「继续」恢复）；建成转 `Operational`。拆除由 `DemolishTask` 推进，完成时移除设施并返还 `BuildCost` 的 50%。任务被取消（无可用工人/作业格不可达）时 `BuildTask` 移除未完成设施、`DemolishTask`/`RepairTask` 回滚到发起前状态；**开发者模式为地图编辑沙盒，仍是即时放置/拆除且免费**（不走任务）；
- 任务携带进度数据（`ProgressFraction`）与实时零件消耗（`TotalPartsCost` / `PartsConsumed`）；表现层据此绘制进度条（设施面板 + 地图设施底边）；
- 设施占地校验（放置/编辑器）：占地格须全部为 Floor 且未被其他设施占用；正在建造/拆除中的设施拒绝重复下达拆除指令（任务板同目标去重为兜底）。
- **任务生命周期基类 `TaskBase`（2026-09-26）**：状态机（Pending → Assigned → InProgress →〔Suspended〕→ Done/Cancelled）、工作者列表、认领/加入资格（`CanAssign`/`CanJoin`/`CanFit`，含「角色须空闲」与 `CanOwn` 归属限制）、优先级、人数上限、状态事件、挂起/恢复与取消释放全部上移至 `TaskBase`；`FacilityWorkTask` 与物品类任务（拾取/取用/穿脱）**共用同一套生命周期**。新增作业类型 = 新增 `${TaskBase}` 的薄子类（设施作业仍建议继承 `FacilityWorkTask` 复用零件与计时机制）；
- **任务目标不再限于设施（2026-09-26）**：`ITask` 新增 `ItemTarget`（物品目标堆）、`Owner`（个人任务归属者，null = 公共任务）、`PreferredWorkCell(c)`（首选作业格：物品任务=物品所在格、就地任务=角色当前格、null=设施四邻选格）、`IsStillValid()`（目标是否仍有效）；`Simulation.TryPickTask` 在认领时校验有效性并解析作业格，**作业格等于角色当前格时就地开工（不寻路，限声明了首选作业格的物品类任务）**；
- **任务板去重键（2026-09-26）**：`TaskBoard.Submit` 由「同设施目标」扩展为 **Owner + 设施目标 + 物品目标** 三元组——设施任务（Owner=null）行为与旧规则逐字等价；个人任务按人各存一份，同一人同一目标只留一条；
- **个人任务（2026-09-26）**：用于「玩家对某人下的指令」（拾取/穿戴/卸下）与「需求驱动的自主取用」——只有归属者本人可认领/加入；`Simulation.AbortCharacterWork(c, true)` 对**公共任务**是「忽略该实例」（留在板上可被他人接手），对**个人任务**则是**直接取消**（个人指令无法转交他人，否则会留下无人可认领的僵尸任务）；
- **物品类任务的写入口一律在 `Simulation`（2026-09-26）**：`OrderPickup` / `OrderEquip` / `OrderWearFromGround` / `OrderUnequip`（预检 → 打断本人当前工作（不加入忽略清单）→ 先把本人置 Idle 再提交（提交即触发派工）→ 必要时补一次认领）与 `TryDropEquipped`（就地落地回退）；表现层不得自行构造这些任务。
- **份额制：谁推进就从谁的背包扣（2026-09-27，口径变更）**：设施作业的零件不是「全局库存远程扣费」，也不是「主工专属」——`FacilityWorkTask.ProgressWork(worker, minutes)` 带上**推进者本人**，按进度比例从他自己的背包整件扣除（合计恰好等于全程成本）；跑完由 `SettleRemainingParts` 补齐余额（保证「跑完恰好扣满成本」，逐帧浮点累计不会漏掉最后一件）。**某人自己的料不足以支付下一整件时，视为「他这一轮到头」**：本人脱离任务（不动进度、不挂起任务、不补料、不拉别人垫），由其余工人继续。注入参数为零件**物品定义**（`IItemDef?`，null = 免费，即开发者模式）。
- **认领即分配份额 + 并行备料（2026-09-27）**：认领设施作业后由 `Simulation.TrySendForParts` 立刻分配份额——**份额 = ⌈未认领需求 ÷ 本轮预计参与者数⌉**，再由背包容量封顶；**参与者数 = 本人 + 场上空闲、没忽略本任务、还装得下零件的角色**，且不超过任务剩余名额（`FacilityWorkTask.InvolvedCount` ＝在场工人 + 在途备料者，**在途者占名额**）。据此派一条服务于本任务（`PickupTask.ServedTask`）的个人拾取任务并让本人退出作业（**不取消、不挂起**），取回后自然重新认领；**先背包、后地面**（手里已有料就直接开工）。要点：**谁闲着谁就一起搬自己那一份**——需求 40 + 三人空闲 → 14/13/13（三人都出发、都投入施工，总速度≈3 倍）；只有一人空闲时参与者=1、份额＝全部剩余，不会因均分而多跑几趟。**反例（务必避免）**：若按「min(未认领需求, 容量)」分配，第一个认领者会把整份需求全领走——开局维修成本 10~15 件 < 单人容量 30 件，于是永远只有一个人取料（这正是实测反馈的根因）。在途预留量按 `PickupTask.IntendedCount`（**总量**，含已取到手的）计入，避免重复取料。**全基地无料可取 → 直接 `SuspendForPartsShortage()`**（面板「零件不足」，补料后点「继续」），不做「发布→取不到→退出→又发布」的空转。取料来源查询为 `Simulation.FindNearestPartsSource`（可达性预检 + 跳过已被未结任务预定的堆）。
- **轮末统一扫描（2026-09-27）**：模拟层每帧驱动完角色后执行 `Simulation.SettleFinishedRounds()`——对「没有工人、也没有在途备料」的未结设施作业做收尾：①**还有人愿意接手**（放宽口径：存在未把它列入忽略清单的角色，不管他此刻忙不忙）→ **自动开下一轮**（`Suspend` + `TaskBoard.Resume`＝重新发布），重新排队、按未认领需求重新分配份额，循环往复直到完成；②**全员都中止过它** → 转「已中止」，等玩家点「继续」。判定放在**下一帧**统一做（而非某个工人离开的瞬间），以避开「取完料的人当帧回来重新认领」的竞态；在途备料（`HasFetchInFlight`）算作「本轮还有人在参与」。
- **认领门槛 `TaskBase.CanTake`（2026-09-27）**：业务前置虚方法（默认恒 true），`CanAssign`/`CanJoin`/`CanFit` **三者共用**——`CanFit`（抢占查询）也查它是必要的：否则手上有活的角色会为一条「别人已把料认领完、自己根本插不上手」的高优先任务白丢当前工作。`FacilityWorkTask` 覆写为先挡两条白跑：①**名额已满**（`InvolvedCount >= MaxWorkers`，在途取料者也算占名额）；②**已有人（含本人）为本任务备料**（`HasOpenFetchFor`——否则任务板会把他派回本任务而不是他手上那条取料任务，实测死锁）；再按「免费模式 / 任务已无零件需求 / 背包已带该种零件 / 还有未被认领的份额且装得下」四选一放行。
- **取料来源抽象 `IItemSource`（2026-09-27）**：`Def` / `Cell` / `AvailableCount` / `TryTake(count, out taken)` / `Return(count)`；今日实现为 `core/Items/GroundItemSource`（物品堆 + 注册表）。**从容器取料**（柜子等设施，参 `resources/facilities/furniture_cabinet.tres`）后续只需新实现一个容器版并并入 `Simulation.FindNearestPartsSource` 的候选集（该方法内已留 TODO 扩展点），任务与调用方零改动。

### 2.4 时间

- `IGameClock`：1 现实秒 = 1 游戏分钟 × 倍速（1/2/4）；暂停时不推进也不触发分钟事件；
- `GameMinuteElapsed` 事件供需求衰减等系统订阅；读档用 `SetTotalGameMinutes` 注入（不触发事件）。

### 2.5 事件总线

- 模拟层与表现层经 `IEventBus`（Publish/Subscribe/Unsubscribe）解耦；事件类型实现 `IGameEvent` 标记接口（现有四类：任务提交/任务状态/设施状态/角色状态）；
- 订阅方须在 `_ExitTree` 退订，防止悬空回调。

### 2.6 资源系统（备用零件）

- `IResourceStore` / `ResourceStore`（core/Resources）为占位资源实现：`Balance` / `TrySpend` / `Add` / `BalanceChanged`；
- **零件库存不再是任务扣费源（2026-09-27 口径变更）**：设施作业的零件改为「**各人自己背包里的实物**」（份额制，见 §2.3 三条 2026-09-27 bullet），故 `GameRoot.ResourceStore`（正常模式为 `GroundItemStore`，余额＝**地上可达**零件堆之和）只保留两个用途——右上角资源监测栏的总量视图、拆除完成时把返还零件投放到设施原位（`DemolishTask`）；`TrySpend` 不再有生产调用方（保留给引擎外测试与占位语义）。**已知取舍**：工人搬在背包里的零件不计入面板余额；被中止者兜里剩下的零件也不回收（按「完全不管」口径，等他下次接活时算进自己的份额用掉）。
- 消耗语义（均由 `FacilityWorkTask.ProgressWork(worker, …)` 统一实现）：**建造**按进度比例从**推进者自己**的背包整件扣除 `BuildCost`、**修复**同理扣 `RepairPartsCost`——料尽即本人退场、由轮末扫描自动开下一轮，**全基地无料可取才挂起**（补零件经「继续」恢复），已消耗不退还；**拆除**不消耗零件，完成时返还 `BuildCost` 的 50%（向下取整，落地到设施原位）；
- 建造不再预扣成本、拆除不再即时返还（改由任务完成时结算）；`MapEditor` 撤销栈已移除金额字段（撤销仅开发者模式可用且免费）；
- **开发者模式一切免费**（建造/拆除/修复均不传零件定义）。

### 2.7 存档系统

- `SaveGameService` 管理 **3 个存档槽**：`user://saves/slot_1..3.tres`（编辑器运行时位于 `%APPDATA%\Godot\app_userdata\Online_AI_Town\`）；
- 存档内容：地图数据（GridMapData 含设施放置）、时钟分钟、角色条目（重建为 Idle，任务不存）、备用零件、开场已播标记、时间戳；
- 槽位规则：主菜单读档与 ESC 暂停菜单保存**共享三槽**；保存模式覆盖已有槽位需二次确认；读档空槽置灰；
- **作业态读档归一（强制）**：任务不参与存档，故设施若在存档时为作业态（建造中/拆除中/维修中），读档一律归一为稳定态——建造中→**不恢复**（未建成即视为未建）、拆除中→运行、维修中→损坏（可再次修复）。不做归一会导致读档后设施卡在作业态且无任务推进；归一在 `GameRoot.RestoreFacility`（`NormalizeState`）单点完成，默认地图与存档槽共用；
- 默认地图 `resources/maps/base_map.tres` 仅开发者模式可覆写，正常模式修改只能进存档槽；
- **地面物品种类自动兼容（2026-09-26）**：地面堆经 `ItemPlacement`（`ItemDef` **资源引用** + 数量 + 格 + 像素偏移）随存档保存与恢复，新增物品种类（如食物/饮用水）**无需为存档加任何字段**，新游戏散落与读档恢复共用同一路径。

### 2.8 剧情动画框架

- 结构：`CutsceneScript`（声明式动作列表，每段动画一个独立小文件）→ 顺序执行 `CutsceneAction`（聚焦/对话/播曲/延时，新动作=新小类）→ `CutsceneDirector` 播放；
- 触发器：一律经 `CutsceneTriggerRegistry` 登记（NewGame / ClockMinute / GameEvent 剧情触发，MusicTrigger / MusicEventTrigger 独立播曲），新增剧情 = 新脚本文件 + Main 注册一行；
- 播放约束：**任何动画开始即暂停时钟**（记住先前暂停态）并禁用 InputPicker / CameraController / MapEditor（恢复先前态而非强制 true），`GameRoot.CutsceneActive` 置位供 UI 拦截输入；
- 音乐与音源解耦：动作/触发只引用音库 Id（`music_library.tres`），换音源零代码；音频文件放 `game/Audio/`，勿用空格中文文件名；
- 占位音频命名 `bgm_<用途>_placeholder.mp3`（文件名不含具体曲名）：换正式音乐只需**同名覆盖文件**，音库 .tres、剧情脚本与代码全部零改动。**验证方式**：覆盖后跑一次 `--import`，确认对应 `.import` 里存在 `path=` 且无 `valid=false`，并用 `GD.Load<AudioStream>(路径)` 确认非 null；剧情脚本只以音库 Id 引用曲（如 `intro_theme`），文件替换**不需要也不应该**改动剧情脚本。
- **音源替换失败的两个坑（务必先查）**：①编辑器运行中覆盖音频文件，导入可能失败并被记成 `.import` 里 `valid=false`（无 `path` 与 `dest_files`、`.godot/imported` 只留 `.md5` 无产物），此时 `GD.Load` 返回 null，播放动作**只打警告不报错**，表现为「脚本看似失效、音乐静默」；修法是删除该 `.import` 与其缓存后重新导入（Godot 不会自动重试已标记失败的导入）；②换扩展名（mp3↔ogg）还须同步改 `.tres` 的 `StreamPath`；播放侧一律用基类 `GD.Load<AudioStream>` 加载（不可写死 `AudioStreamMP3`），循环经 `Set("loop", 布尔)` 统一设置，否则换格式后静默失声。
- **视频音轨与背景音乐分离（强制）**：`VideoStreamPlayer` 循环重启视频时其内嵌音轨会在接缝处**间歇爆音**（听感像接触不良，且每次位置/有无都不固定），故凡「视频配乐」的场景（当前为标题界面）一律把视频音轨静音（`VolumeDb = -80`）并把同一段音源拆成独立音频文件，用 `AudioStreamPlayer` 独立循环（Ogg Vorbis 精确循环、无接缝）；拆轨用 Ogg **页面级**提取即可（按逻辑流 serial 取页，无需重编码，音轨与原视频等长）；仅当独立音乐起播失败时才保留视频自带音轨发声；
- **已知引擎产物（勿追）**：退出时若有 `AudioStreamOggVorbis` 正在播放，引擎会打印 `WARNING: N ObjectDB instances were leaked at exit` 与 `ERROR: N resources still in use at exit`（指 Ogg 播放器相关对象）。这是 Godot 退出清理顺序问题——最小复现：纯 GDScript 加载同一 .ogg 播放后退出即复现，`_exit_tree` 里 `stop()` 无效；同场景播放 MP3 则无任何输出。不影响运行与内存，勿再排查。

### 2.9 UI 构建约定

- 模式：纯代码布局（PanelContainer + VBox/HBox）+ `Setup(...)` 注入依赖 + `_ExitTree` 退订；场景文件仅根节点挂脚本；
- 顶栏分区：左上角注册制菜单栏（起点 16，自左向**右**生长）与右上角时间流速条（`SetAnchorsAndOffsetsPreset(TopRight, Minsize, 12)` + `GrowHorizontal = Begin`，自右边缘向**左**生长）分列两侧——新增顶栏组件必须明确归属侧并靠边锚定，**不要居中**（居中会与随菜单项增加而变宽的菜单栏重叠；菜单栏 10 项时宽约 694px）；
- 菜单图标：菜单项 `MenuItemDef.IconPath` 非空且贴图可加载时渲染图标按钮（主题常量 `icon_max_width` 限幅为 28，显示名转为悬停提示），否则回退文字按钮——新增菜单入口只需按 `menu_<菜单Id>.png` 放置贴图并注册定义，零改框架；菜单 Id 同时是 PanelHost 的面板注册键，未注册面板的入口点了会「按下但无面板」，故每个入口都应注册面板（未有实现时用 `PlaceholderPanel`）；
- 标题动态背景：`TitleScreen` 优先播放 `res://game/Video/title_background.ogv`（`VideoStreamPlayer`：`Loop` + `Expand` + 全屏锚点，入树后再设锚点）；**Godot 原生仅支持 Ogg Theora**（实测 `VideoStream` 可识别扩展名仅 `ogv/tres/res`，mp4 等须外部工具转码），文件缺失或流加载失败时回退静态贴图且不中断；视频音轨一律与背景音乐分离（见 §2.8），且**以音乐为时间基准同步视频循环**（`_Process` 检测音乐播放位置回绕即 `StreamPosition = 0`），否则两条独立循环会因时长差异逐圈累积漂移；
- 输入冻结：需要临时禁用输入的组件（InputPicker/CameraController/MapEditor）一律带 `Enabled` 开关，禁用/恢复「先前态」而非强制值；
- 相机边界：`CameraController` 约束为「视野矩形（视口 ÷ 缩放）恒不超出地图世界区域（= 背景图铺满范围）」——**最小缩放为动态值** `max(视口宽/世界宽, 视口高/世界高)`（两轴比值取**较大者**，保证两轴都不溢出；下限兜底 0.2），缩放/平移/视口尺寸变化后统一夹紧，世界小于视野时该轴居中；画面初始缩放取同一公式（不得使用「视口/世界」的较小值，否则另一轴会露出地图外）；
- 交互入口：**建造面板（EditorPanel）不常驻**，与其它菜单面板同属左上面板区、由菜单「建造」经 PanelHost 互斥开合，面板可见即建造模式（Main 为唯一协调者，面板可见性 → MapEditor 进出编辑模式，反向 EditModeChanged → 开合面板；两侧均幂等，不循环触发）；正常模式保存走 ESC 暂停菜单（与主菜单共享槽位）；建造面板的保存按钮仅开发者模式显示。
- **建造面板的设施选择（可视化 + 分类过滤）**：工具为「建造 / 拆除」（开发者模式另有「地形 / 功能区」画笔）；建造工具下先由**分类按钮行**（HFlowContainer，取自 `FacilityCatalog.Categories`）过滤，再以「占位图标 + 名称」的**图标网格**（ScrollContainer + GridContainer，Button 图标在上、名称在下）选择设施——替换原 `OptionButton` 下拉。分类与设施完全数据驱动（加设施/加分类只改 .tres 与 `Category`），**禁止在 UI 里写死设施清单**；无贴图的设施以分类色块纹理作占位（`EditorPanel.CategoryColor`），配置了 `IconTexturePath` 则直接用贴图；
- **撤销仅开发者模式**：正常模式「完全屏蔽」撤销——按钮不显示且 `MapEditor.Undo()` 与 Ctrl+Z 均有 `DevMode` 守卫（正常模式的建造/拆除走任务流程，无撤销语义）；
- 选中系统：**人物与设施选中互斥**，由 `InputPicker` 统一拾取——点击时取光标半格像素阈值内的全部角色为候选（按「距离升序 + 登场顺序」排序，**不依赖渲染层级**，否则提升图层后叠放循环顺序会抖动），当前主选在候选内则循环切到下一个，否则取首个；候选为空才落到设施命中（格子精确 + 四邻容差）。事件顺序契约：命中角色→先发 `FacilityPicked(null)` 再发 `CharacterPicked(角色)`；命中设施/空白→先发 `CharacterPicked(null)` 再发 `FacilityPicked(...)`，调用方按「后到达者生效」处理即可（二者皆 null 表示点击空白）。**按住左键拖动超过约 6 屏幕像素进入框选**（`BoxSelectChanged` 上报世界坐标矩形供 `SelectionBoxView` 绘制，松开时 `BoxSelectionCommitted` 提交矩形内全部角色，支持多选）。选择集统一由 Main 应用（`SetCharacterSelection`）：选中者 `ZIndex=1` 提升到设施之上、主选 `MoveChild` 到实体层最后以保证重叠时可见、面板显示主选详情（多人时另显「已选 N 人」）、并回写 `InputPicker.SelectedCharacter` 作为循环基准。拾取器使用输入事件自带坐标经画布变换逆变换得到世界坐标（不用全局鼠标位置，便于无头注入事件验证）。

- **窗口吞掉全局输入（滚轮/中键）**：滚轮即便经过 `MouseFilter=Stop` 的面板也可能落到 `_UnhandledInput`（`ScrollContainer` 到达顶/底边界时不消费滚轮，事件遂穿透为地图缩放），故由 `CameraController` 统一守卫——鼠标落在**任一已注册 UI 窗口**内时不缩放、不启动中键平移（`when !UiWindowRegistry.IsOverWindow(事件坐标)`；中键释放与平移位移分支不设守卫，保证已开始的拖拽能正常结束）。窗口在装配处登记：`Main.BuildUi/SetupMenus` 直接创建的窗口逐一声明，`PanelHost.Toggle` 对惰性实例化的面板自动登记并在 `_ExitTree` 注销；**鼠标穿透型元素（`WorldHint` 等）刻意不登记**。新增窗口必须登记，否则窗口上的滚轮会穿透为地图缩放；
- **地面物品的悬停与命中（2026-09-26）**：**图标矩形口径由 `ItemStackView.IconRect(stack, mapView)` 静态方法唯一提供**（中心 = 格中心 + 格内像素偏移，边长 `DrawSize=24`），绘制、悬停命中与右键菜单**共用同一口径**，杜绝像素偏移漂移。悬停**仅在有主选角色时**生效（`InputPicker` 内判定），命中框 = 图标矩形外扩 `HoverTolerancePx=2`（28 见方，**小于整格 32**）；命中最近一堆（多堆取框中心离光标最近者）并发 `ItemHovered(stack?)`，由 `Main` 同步 `ItemStackView.Hovered`——悬停画**蓝色**描边（外扩 1px，比选中黄框更贴紧），选中黄框（外扩 2px）可并存（蓝在内、黄在外）。选择集变化与悬停对象消失时清悬停（逐件转移导致的其它堆变化**不**清，避免蓝框闪烁）；

### 2.10 物品流转（拾取 / 消耗）与装备穿脱

- **基础单位是「个」（设计哲学，强制）**：重量、容量、转移、消耗、穿脱一律**按个结算**（`单位重量 × 个数`、**逐个转移**、消耗 1 个）；`ItemStack`（堆）**只是「用一张图显示多个」的表现分组**，不承载领域语义——后续任何涉及物品数量的逻辑都不得出现「整堆」概念（`MaxStack` 只决定拆成几张图）；
- **逐件转移（拾取/取货模型）**：`PickupTask`（手动拾取）与 `ConsumeTask` 的取货阶段都按「每件一个转移周期」推进——默认 `PickupTask.TransferGameMinutesPerItem = 0.5` 游戏分钟/件，**无固定总时长**，完成条件是**动态终点**（装不下下一件 / 目标堆已空 / 计划件数用尽）；进度 = 已转移件数 ÷ 计划件数；**取消/中止无回滚**（已转移的留背包、未转移的留地面）；
- **取货来源抽象与「只取所需」（2026-09-27）**：`PickupTask` 面向 `IItemSource`（`GroundItemSource` 包 `ItemStack` + `ItemRegistry`），并新增 `maxCount` 计划上限与 `servedTask` 服务链接——玩家手动拾取传不限量（装满为止）、不挂链接；**为设施作业备料**则传「分配到的份额」并挂上它服务的作业（供作业侧计算未认领需求与轮末判定，供中止时连带退出）。`ItemTarget` 仅在来源为地面堆时给出该堆（保住物品进度条）；取出后装入背包失败时经 `IItemSource.Return` 原样放回（物品不凭空消失）。备料链路见 §2.3「认领即分配份额 + 并行备料」；
- **容量查询**：`CharacterInventory.MaxAddable(def)`（按剩余容量 ÷ 单位重量向下取整；0 重量物品返回 `int.MaxValue`）供「逐件判定装得下」与玩家指令的即时预检共用；`Simulation.OrderPickup` 预检失败直接回调 `PickupOutcome`（`NoCapacity`/`Gone`/`Unreachable`），表现层用 `WorldHint` 在物品处提示；
- **可消耗物品**：`IItemDef` 新增 `ConsumableKind`（None/Food/Water）、`NeedRestoreAmount`、`ConsumeGameMinutes`；`ConsumableCatalog`（core/Items）由 `GameRoot` 在装配时按固定路径注册（`food_ration.tres` / `water_bottle.tres`），供模拟层按种类反查；消耗完成经 `NeedSystem.Restore(c, NeedId, amount)` 恢复需求（**触发 `NeedsChanged`**，面板自动刷新；需求层不反向依赖物品层，映射留在 `ConsumeTask` 内）；
- **需求驱动的自动取用**：`Simulation.OnGameMinuteElapsed` 在需求推进后扫描每名角色——进食/饮水 < `AutoConsumeThreshold=30` 时提交个人取用任务（**背包优先**：背包有货→就地消耗不寻路；否则找「种类匹配 + 未被其他未结任务占用 + 本人可达」的最近堆前往取用）；优先级 <30 → `P8`、<`CriticalConsumeThreshold=10` → `Urgent`（不可被「人物中止」忽略）；单趟拾入上限 `AutoPickupMaxTrip=3` 件（随后就地消耗 1 件）；已有未结取用任务时不重复提交；
- **装备效果**：`IItemDef` 新增 `WorkSpeedBonusPercent` / `MoveSpeedBonusPercent`（0.1 = +10%），生效点为 `Simulation.AdvanceWork`（`专长倍率 × (1 + 工作效率加成)`，对全部作业生效不限专长）与 `AdvanceMovement`（`移动速度 × (1 + 移速加成)`）；负重容量沿用 `ContainerCapacityKg`；`CharacterInventory.WorkSpeedBonusPercent` / `MoveSpeedBonusPercent` 提供 Σ 加成，`CharacterPanel` 装备区末行显示「装备效果：…」；
- **穿脱一律任务化（不再瞬时写入）**：`EquipTask`（背包→槽位就地耗时 `EquipGameMinutes=5`；或**地面→槽位**：走到物品格 → 计时（含取下与穿上，**不产生「拿在手上」的中间状态**）→ 完成时一次性「地面扣 1 件 + `TryWearDirect` 入槽」）、`UnequipTask`（就地耗时 `UnequipGameMinutes=5`）；入口为人物面板按钮（`OrderEquip`/`OrderUnequip`）与右键菜单「穿戴」（`OrderWearFromGround`）；面板订阅 `TaskStateChangedEvent`，在本人个人任务终态时刷新；
- **换装/卸下的回退规则**：同槽旧装备优先回背包（`TryEquip`/`TryWearDirect` 内部试算，超重则拒绝）；**背包放不下时改走「就地落地」**——`Simulation.TryDropEquipped(c, slot)`（角色所在格优先、其次四邻，须为地板且未被设施占地；无格可放则**保持装备**并回调提示，不做任何改动）；地面穿戴时若旧装备需落地，任务会先做可行性预检，失败则整笔取消并回滚（物品不丢）；
- **测试与验证**：`tests/ItemTaskFrameworkTests.cs`（逐件节奏、动态终点、预检回调、取消无回滚、去重键、个人任务归属与中止语义）与 `tests/ConsumeAndEquipTaskTests.cs`（需求恢复、两种取用模式与分钟扫描、两条穿戴路径与落地回退、装备效果、`MaxAddable`/`TryWearDirect`/`TakeEquipped`）；**份额制备料链路**由 `tests/RepairTaskConsumptionTests.cs`（各扣各包、料尽自退、收尾扣满）与 `tests/PartsSupplyTests.cs`（并行分份 30/10/0、轮末自动续轮、无料直接挂起）覆盖，交接语义由 `tests/AbortAndMoveTests.cs`（右键移动＝中止并交接、无料被动中止集成）覆盖；无头探针覆盖悬停命中框、右键菜单、拾取链路、自动取用、穿脱、并行备料与中止交接、存读档往返（探针用后即删）。
