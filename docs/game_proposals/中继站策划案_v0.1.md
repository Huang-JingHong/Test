# 《中继站》游戏策划案

> 暂定项目名｜v0.1｜前期概念设计｜2026-09-05  
> 本文用于统一团队对游戏方向及原型范围的理解。具体数值、内容数量和实现细节在原型验证后确定。

## 1. 项目概述

《中继站》（**原型v0.1**）是一款以基地修复为核心的**单机**，**殖民地生存模拟**游戏。玩家管理三名因飞船事故迫降的幸存者，在废弃的太空采矿中继站中分配工作、维持生存、逐步恢复设施，最终向外界发出求救信号。

| 项目 | 规划 |
| --- | --- |
| 游戏类型 | 殖民地管理、生存模拟 |
| 发布平台 | Windows，单机离线 |
| 开发引擎 | Godot 4.7.2 |
| 画面形式 | 2D 俯视角，圆环形基地地图 |
| 核心操作 | 指定任务、调整工作优先级，角色自主执行 |
| 时间机制 | 实时运行，支持暂停与加速；正常速度下现实 1 秒约为游戏 1 分钟 |
| 原型时长 | 首次游玩约 **30 分钟**，作为体验目标 |
| 目标体验 | 从艰难维生到逐步掌控基地，发送求救信号 |

## 2. 游戏设计思路

### 2.1 世界观设定

人类已经大规模定居月球、火星及火星与木星之间的小行星主带。采矿设施、运输节点和分散聚落构成了小行星带的生活网络。
一艘载有三人的小型飞船遭遇事故，迫降至一座废弃采矿中继站。站内设施老化、物资有限、通信中断。幸存者必须利用现有条件恢复生命维持与通信系统。

（与周边居民建立联系、贸易及冲突属于后续扩展方向。原型v0.1聚焦中继站内的求生过程。）

### 2.2 设计理念

- **基地修复：**通过恢复预设设施，让基地从失效走向稳定，形成清晰可见的进展。
- **制造简单选择：**三人的能力、需求与任务安排相互影响，玩家决定工作的轻重缓急。
- **信息作为收益：**从观察异常，到识别状态，再到读取精确数据，逐步提高玩家对于环境的判断能力。
- **故事来自系统互动：**角色特点、玩家决策与规则事件共同形成经历，叙事者负责调节节奏。
- **保持原型规模可控：**采用简化模拟和固定内容，优先验证游戏是否完整、有趣、易理解。

### 2.3 核心玩法

**观察问题 → 分配任务 → 回收资源 → 修复与升级 → 改善生存条件 → 应对新事件。**
玩家主要权衡生命维持、角色休息、资源获取和通信修复的先后顺序。角色根据自身需求和工作优先级自主行动。
原型流程分为三个阶段：

1. **紧急求生：**了解基地状况，恢复基本氧气与供电。
2. **稳定运转：**安排三人分工，获取物资，**提升环境监测能力。**
3. **恢复联系：**完成通信修复，在维持生存的同时发出求救信号。

### 2.4 参考案例

| 参考作品 | 主要借鉴方向 | 本项目的取舍 |
| --- | --- | --- |
| 《环世界》 | 小人自主行为、**工作优先级**、需求与特质、**规则叙事者**、清晰的俯视角表现 | 保留三人管理与事件驱动体验，简化社交、战斗及角色模拟 |
| 《缺氧》 | 生存设施之间的依赖、系统状态反馈、升级带来的管理能力提升 | 使用**简化氧气和供电系统**，以少量设施升级替代大型科技树 |
| 《了不起的修仙模拟器》 | 角色背景差异、**群体经营**与长期发展感 | 作为角色塑造与经营氛围参考，原型不引入复杂成长体系 |

## 3. 角色设计

原型采用三名固定角色。每人具有简短背景、工作特长和少量特质，形成不同的分工倾向。
| 角色方向 | 背景倾向 | 主要职责 |
| --- | --- | --- |
| 维修人员 | 地球出身，熟悉设备维护 | 设施修复与升级 |
| 系统操作员 | 火星出身，熟悉站点系统 | 调查、监测与通信操作 |
| 外勤作业人员 | 小行星带出身，熟悉外围作业 | 资源回收与舱外活动 |

角色的基本需求包括呼吸、进食和休息。需求恶化会**影响工作能力**，并可能危及生命。所有角色都能执行主线必要工作，**特长主要影响效率**。
（不同出身的环境适应差异作为后续探索方向，原型暂不确定具体氧气浓度偏好。暂不制作复杂社交、疾病和技能成长系统。）

## 4. 系统介绍

### 4.1 工作与优先级

玩家通过设施或**任务面板**指定工作，并调整每名角色的工作优先级。角色综合需求、任务条件和优先级选择行动。界面应明确反馈当前工作及无法执行的原因。

### 4.2 生存与资源

以全站共享的氧气、供电状态支撑生存压力，以食物、回收材料和维修零件支撑消耗与修复。
关键通关物资应有可靠获取途径，避免随机结果造成无法继续的局面。

（原型不模拟逐格气体流动、温度及复杂管线。）

### 4.3 基地与设施

地图采用**圆环形基地**布局，包含生活、动力、生命维持、仓储气闸及通信等功能区域。
设施设计围绕供电、制氧、休息、监测、回收和通信展开，形成容易理解的功能区。

（设施位置预设，玩家进行修复、启停与升级，暂不开放自由建造。）

### 4.4 信息与监测升级

原型**重点验证的特色系统**。后台采用统一模拟，监测能力决定玩家能读取的信息深度。
| 阶段 | 信息表现 |
| --- | --- |
| 行为观察 | 通过喘息、停工、设备异常等迹象判断问题 |
| 状态监测 | 显示氧气不足、正常及变化方向等定性信息 |
| 精确监测 | 显示储量、变化速度与预计可维持时间 |

原型先围绕**氧气验证完整层级**。基础任务条件和操作反馈始终清楚可见，避免信息隐藏造成无从下手。

### 4.5 舱外活动（EVA）

以简化外出任务获取补给和维修资源。玩家选择任务与执行者，角色离站后以状态和返回时间展示进展。
主要取舍是外出收益、补给消耗，以及基地暂时减少一名劳动力的影响。

（原型阶段不表现具体作业过程。）

### 4.6 规则叙事者（后续制作方向）

叙事者根据资源压力、角色状态、设施进度和近期事件，安排故障、机会或平静期。
事件需给玩家留下应对空间，避免连续叠加重大危机。日志记录关键事件与行动结果，帮助玩家回顾本局经历。

（原型只制作一种叙事节奏，使用条件、权重与冷却规则，同时**暂不考虑接入大语言模型**。）

### 4.7 目标与结算

恢复通信并完成求救信号发送即为胜利；全部角色死亡则失败。结算简要展示幸存人数、耗时及关键经历。

## 5. 界面与视听设计

### 5.1 界面结构

| 区域 | 主要内容 |
| --- | --- |
| 顶部状态栏 | 时间、暂停与加速、库存、已解锁监测信息 |
| 角色栏 | 三人状态、当前任务与异常提示 |
| 地图主视图 | 基地设施、角色活动、可交互对象 |
| 选中信息面板 | 角色或设施详情，以及可执行操作 |
| 工作面板 | 角色分工与工作优先级 |
| 目标与事件区 | 当前目标、重要警报、事件日志 |

界面优先回答三个问题：**当前出了什么问题、谁在做什么、玩家可以做什么。**

### 5.2 美术与声音方向（后期制作方向）

暂定采用接近《环世界》的简洁 2D 表现，以清晰轮廓、俯视设施和有限动画呈现人物与基地。通过服装、配色和图标区分角色与状态，**最终画风由美术确定。**
声音重点服务于状态判断与氛围：设备运行、停机、警报和通信反馈，让废弃空间站既有孤立感，也能随着修复逐渐恢复生机。

（原型阶段不引入声音系统）

## 6. 范围与开发规划

### 6.1 范围边界

**原型v0.1包含：**一张固定地图、三名固定角色、基础需求与工作优先级、预设设施修复、氧气监测升级、简化 EVA、少量规则事件、简单通关流程与基础存档。

（**后续制作方向：**自由建造、贸易、战斗、派系、复杂社交、**完整的EVA流程**、**修复飞船后类似FTL的探索**、完整科技树、多地图、精细环境模拟及**大语言模型接入**。）

### 6.2 团队与阶段

团队由一名美术、一名主程序、三名副程序组成，每人每周投入**约 5-8 小时**。策划与项目管理由现有成员兼任，主程序负责技术接口与集成。
| 阶段 | 阶段成果 |
| --- | --- |
| 基础验证 | 灰盒地图中，一名角色可完成修复任务 |
| 生存闭环 | 三人分工、需求、资源与设施协同运行 |
| 完整流程 | 从迫降开局到求救结算可完整游玩 |
| 特色验证 | 加入监测升级、叙事者与关键日志 |
| 试玩打磨 | 优化引导、节奏、表现和稳定性 |

**按最低每周 30 人时投入，暂以约 8 周作为规划起点。

### 6.3 主要风险与验证重点

- **范围膨胀：**新增想法统一进入后续清单，优先完成原型闭环。
- **协作与集成：**模块明确负责人，尽早约定接口，每周演示可运行版本。
- **反馈不清：**通过外部试玩验证玩家能否识别问题、理解操作和失败原因。
- **节奏失衡：**观察是否出现长时间等待或连续危机，调整任务耗时与事件间隔。

原型标准：玩家能理解生存问题，调整三人分工，感受到修复与监测升级的价值，并完成一段简单的求生。
